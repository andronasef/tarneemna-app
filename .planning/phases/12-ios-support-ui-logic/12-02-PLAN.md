# Plan 12-02: iOS Firebase Registration & Platform Logic

## Objective
Register and configure the iOS application in Firebase, add `GoogleService-Info.plist`, update `lib/firebase_options.dart` via FlutterFire CLI, configure `AudioSession` for iOS background playback, and verify sandboxed offline storage.

## Proposed Tasks
1. **Task 12-02-01: Firebase iOS Setup & Configuration**
   - Register iOS app with bundle ID `com.increase.tarneemna` in Firebase (`tarneemna` project).
   - Place `GoogleService-Info.plist` into `ios/Runner/`.
   - Run `flutterfire configure` to generate the official iOS `FirebaseOptions` in `lib/firebase_options.dart`.
   - Verify `Firebase.initializeApp` succeeds on iOS without throwing `UnsupportedError`.

2. **Task 12-02-02: Audio Session & iOS Background Playback Integration**
   - In `lib/features/audio/data/sources/tarneemna_audio_handler.dart`:
     - Configure `AudioSession` specifically for iOS (`AVAudioSessionCategory.playback`, `AVAudioSessionMode.default`, `AVAudioSessionCategoryOptions`).
     - Verify `audio_service` media notification & remote command center sync for lock screen, Control Center, and Dynamic Island.

3. **Task 12-02-03: iOS Sandbox Offline Storage Verification**
   - In `lib/features/downloads/data/sources/offline_storage_service.dart` and `download_manager_service.dart`:
     - Verify file paths resolve to `getApplicationDocumentsDirectory()` within iOS sandbox containers.
     - Validate that downloaded hymns persist and are playable from the local sandbox file path on iOS.

4. **Task 12-02-04: AppDelegate Swift Setup**
   - In `ios/Runner/AppDelegate.swift`:
     - Ensure standard Flutter plugin registration (`GeneratedPluginRegistrant.register(with: self)`).
     - Configure any iOS lifecycle callbacks required by audio or background tasks.
